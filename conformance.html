Every claim on this page is executed, not described.

The sponsor's reference browser runtime is copied into ./runtime/ and used unchanged. Each button below builds an Engine from that bundle, points it at a published file on this origin, runs a real turn and prints what the runtime itself said. The published router is browser://mock, so these probes need no API key and send nothing to a model provider; the refusals, budgets, policies and citations they exercise are the same code paths a keyed run uses.

Check 7's four refusals are published as real fixtures on this origin (./broken/, ./cyclic/, ./budget/, ./deny/) rather than simulated, because "the runtime would refuse" is only evidence if something is actually there to be refused. The same seven checks are also run offline against the identical files by node test/interop.mjs, whose generated report is linked from the manifest.

This is the sequence the two-minute video shows.

1 · An invalid published network is stopped not run

spec §6.7 — "Stop an invalid network … with a visible error". ./broken/empty_graph.network.json publishes a network with no agents and no front man.

2 · A composition cycle is stopped not run

spec §6.7 — "…a composition cycle…". ./cyclic/composition_cycle.network.json hands its own question back to itself, so the second hop is already in the call chain.

3 · An over-budget composition is skipped not run

spec §6.7 — "…an over-budget request…". ./budget/budget_probe.network.json names the same peer twice in one query; the runtime allows one consultation per peer per query.

4 · A denied origin is refused before transport not run

spec §6.7 — "…and a denied origin with visible errors". This site's own manifest denies https://oaw-denied-fixture.pages.dev, and ./deny/deny_probe.network.json asks to contact it.

5 · Peer contact asks you first, and shows what it will send not run

spec §3.2 / §6.4 — the exact named network at a second origin is loaded only after the user approves, and then runs here. This probe uses the shopfront's real network, whose links.json binds fbr_rules_authority. You decide Allow or Decline when the card appears.

6 · Arguments are validated, and a write waits for you not run

spec §3.1 — "the runtime must validate arguments and show the user the destination and arguments before a write". This origin registers five local site actions, four read and one write. The dialog you get is the runtime's own reviewActions(), not a page copy of it.

What this page cannot prove on its own

  • The mock router answers in summaries truncated to 1200 characters, so a probe's visible sentence is not the evidence — the trace table and the request log underneath it are.
  • Probes 1–4 stay on this origin. Cross-origin behaviour (probes 5 and 6's peer read) additionally depends on the hosting headers of the second site, which only a deployed origin can show.
  • The budget values the runtime enforces — 4 remote calls, 1 call per peer, 24 agent calls, depth 5, a 90-second deadline — are fixed in runtime/engine.js. Our published max_execution_seconds is a hint, and this page says so rather than claiming we set it.
  • Whether a real provider answers these questions well is a video item, not a conformance result.
